# Plan: Refactor Configuration Tab

## Context

The Configuration tab in `dashboards/web/static/index.html` (lines 157–347) has accumulated multiple issues over time. It was partially fixed but never structurally rethought. The form mixes three conceptually distinct things into one long scrolling page:

1. **Broker connection** — provider selection + credentials
2. **Risk management** — capital, lot size, risk limits
3. **Environment-variable-only credentials** — sensitive fields the UI pretends to save but actually can't

The JavaScript is 300+ lines of mixed concerns with no clear separation.

---

## Goal

Split the tab into focused, single-responsibility sections. Improve usability, reduce sprawl, make the code maintainable. The broker-specific credential fields should accurately reflect what can and cannot be saved.

---

## Design Decisions

### Structure: Two tabs instead of one

Replace the single scrolling form with a tabbed sub-navigation:

| Sub-tab | Purpose |
|---------|---------|
| **Connection** | Broker provider, mode, connection test, all credential fields |
| **Risk** | Capital, lot size, risk limits, frequency |

Rationale: These are logically separate. A user changing risk params doesn't need to scroll past 30 credential fields.

### Rename "Configuration" to "Settings"

More standard UX label.

### Restructure the Connection sub-tab

Split credentials into two groups with clear visual separation:

**Group A — "Saved via API"** (non-sensitive, persist to `config.json`):
- Broker Provider, Trading Mode, Client ID, Consumer Key

**Group B — "Env vars only"** (sensitive, clearly marked as read-only/persistence-disabled):
- Password, API Key, API Secret, Access Token, TOTP Secret, enctoken
- Each field gets a `<div class="env-only-badge">🔒 Env var only — cannot be saved from browser</div>`
- Fields are functional for the **Test Connection** flow, but clearly documented as non-persistent

Rationale: The previous UX misled users into thinking they could save passwords via the form. This makes it explicit.

### Restructure Risk sub-tab

Keep current fields, add inline validation messages, no other changes needed.

### JavaScript refactor

Break the 300-line `<script>` into clearly separated concerns:

```
ConfigState         — holds _savedConfig, _pendingProvider, dirty tracking
ConfigBroker        — loadBrokerList(), onBrokerChange(), buildCredentials()
ConfigConnection     — testConnection(), showModal(), closeModal()
ConfigRisk          — validateRisk(), applyCredentials(), resetForm()
ConfigSave          — saveConfig() with validation + feedback
ConfigTab           — showTab() entry point, WebSocket bridge
```

Each group is 15–40 lines max. All global state is explicit. No function is longer than 40 lines.

### Broker-specific field map

Trim `PROVIDER_FIELDS` to only the 9 brokers with conditional fields:
`angelone, kotak, kotak_neo, finvasia, motilal, choice, aliceblue, iifl, geojit`

Fields for Zerodha (enctoken), Master Trust, mStock, Moneysukh exist in the HTML but are never shown because they have no `PROVIDER_FIELDS` entry. Either:
- Add them to the map (restore visibility), or
- Remove them from HTML if truly unused

Decision: Add to map — these brokers are supported and users need to see these fields when they select the broker.

### Input validation

Keep current `validateConfig()`. Display errors inline below the Risk section header rather than only in the feedback box.
